# TRO-APFG：M1–M6 场景及训练方案（研究提案 v0.1，2026-11-22）

> **状态：DESIGN_ONLY / NOT_RUN。** 本文是 M0 之后的研发规划，不意味着已经训练或验证算法。最终科研缺口和 T-RO 创新性尚未确认。相关强基线需要读原文并在相同任务协议下公平比较。

## 0. 现有仓库实测基础（2026-11-22 main）

- M0 真正通过的设备是 **RTX 3090 24 GiB + Isaac Sim 4.5 + Isaac Lab 2.0.2**，并非原计划 4090 / Isaac 5.1。30 种 YCB 下载/转换，13 种物理验证，Franka、双 RGB-D、S1 密集桌面、S2 物理自然堆叠已验证。证据见 `docs/M0_REPORT_ZH.md`。
- 同仓库已添加与真机硬件对应的 **SR5 六轴 + PGIA-140-80-W + D435i**：源装配近似外参，已知坐标真实物理 Push/Grasp 与接触证据通过；GraspNet 单物体真实 RGB-D 六维候选推理和一例物理抓取通过。证据见 `docs/SR5_GRASPNET_REPORT_ZH.md`。不是杂乱抓取成功率、也不是 Flip/Active 成功证明。
- `apfg/primitives/sr5_control.py` 实现关节速度限制、坐标 IK、已知位姿的 push/grasp；`apfg/perception/graspnet_candidates.py` 是单帧观测抓取候选/有限外形过滤，不具备完整路径碰撞保证。
- 核心研究以 SR5 为主，Franka 可作平台泛化补充。禁止为了换新机器人重新安装环境。所有新文件仍保存在当前项目目录；视频本地存放，小型证据和代码推送 `LemonQC/GraspPushFlick`。

## 1. 任务边界

给定可识别/至少部分可见的目标物体，机器人从当前杂乱场景将**指定目标完整抓持并取出工作区**。不要求非目标物体到达任何目标布局，不以清空箱体为任务，不鼓励无关扰动。

可选择的操作：View（主动移动腕部相机）、Push（物体位置与可达空间改变）、Flip（绕水平分量显著的轴产生三维倾倒/滚转或支撑姿态改变，纯 yaw 不算）、Grasp（真实双指接触抓持并完整取出）。**不规定必须调用全部四种技能**；可以直接抓。

主要成功判据：指定目标被实际抓起、抬升、在指定安全区域外稳定保持，非目标未发生灾难性掉落/碰撞；记录动作数、执行时间、非目标位移、跌落、接触、最终可抓性与观测量。

## 2. 三类训练困难场景 + 一个混合测试

**C（clearance / Push 可能有用）**：开口桌面或浅盘、4–7 件非重堆物体，指定目标有可见接触点但夹爪通道被邻近物体占用。通过非目标的局部推动可改善接近空间；确保不存在直接抓的简单捷径，且多个动作有可能成功，不能只用固定推距模板。

**F（orientation / Flip 可能有用）**：目标在不利支撑面上，如矮扁盒/薄块/不对称工具，最好的稳定抓取区域紧贴工作台或被当前姿态遮住；倾倒、滚转或局部辅助翻身改变稳定支撑姿态。必须是 SR5+80mm 爪物理可实现、可测量的姿态改变。禁止要求所有物体180度翻转；轴对称滚动需考虑等价姿态，单纯 yaw 不算 Flip。

**V（visibility / Active 可能有用）**：固定视角中目标部分被遮挡，腕部运动后有潜在新增可用信息；物体可以保持不动而获得新视角。不要把完全不可辨认的目标当成已知目标，避免以 oracle ID 泄漏任务答案。

**Mix（多困难组合，只用于后续混合验证）**：从上述真实物理机制组合出清晰且可解的情形，可出现 View→Flip→Grasp、Push→Grasp、View→Push→Flip→Grasp 等，但这些不是固定答案。不要为了迫使四技能联合而制造每种情况都必须按固定顺序执行的脚本。

**Direct（对照）**：原本可直接抓，四技能系统必须学会不增加无效动作；保留作为训练/测试的一部分。

环境不宜一开始完全随机 15 件物体深重堆叠；先使用已验证 YCB 资产中**真实宽度/抓持方式与80mm夹爪兼容**的少量子集，记下碰撞、质心、摩擦估计偏差。建议最初选 6–10 件可稳定操作对象、3–5 件/场景，再渐进提高数量。场景通过落体稳定/碰撞/可执行性检查筛选，不靠人为在 rollout 里重置物体位姿。

## 3. 训练任务与数据接口

输入（学生策略）：多视角真实 RGB-D、当前可见目标 mask/目标身份的公平提示、机器人本体状态、有限时序历史、GraspNet 候选与可执行性、动作执行后的实际观测。真实隐藏物体位姿、完美物理参数、分布外的目标标签仅用于离线诊断、场景生成与评测，不在 RGBD 部署时偷渡。

**动作是带参数的操作而非仅四分类**：
- View(camera pose / reachable next-best-view)，需真实机械臂运动。
- Push(contact point, direction, height, distance, speed)，距离连续可调，不固定若干毫米。
- Flip(contact, push/pivot axis, stroke/force-control surrogate)，物理倾倒/滚转并记录新支撑状态。
- Grasp(6-DoF TCP pose, opening, approach, extraction motion)，复用已验证 GraspNet 权重与 SR5 运动接口，先做全臂/夹爪扫掠碰撞检查。
动作集为每次观测时提出的有限候选 + 相应连续参数，可根据类型使用 mask 与参数化分布。

信息记录：固定/腕部 RGB-D、相机 K/T、候选及筛选原因、动作参数、真实 contact/物体与关节轨迹、取出判定、完整视频；所有 train/val/test 在场景种子+物体实例上隔离，去除 YCB/GraspNet 重复扫描物体造成的数据泄漏。

**禁止先构造“C=>Push、F=>Flip、V=>View”的人工标签训练一个四分类器。** 这会把研究变成手写启发式的模仿。真实技能选择要由共同目标和物理试验反馈决定。

## 4. 学习路径（逐级启动，不立即大规模 RL）

**阶段 A — 物理原语与受控候选**：先把 SR5 可达的 View、Push、Flip、Grasp 都做到真实闭环可执行（不一定一次成功）；保留各操作可行动作与失败证据。复用现有 GraspNet 和已测 SR5 控制器，不重训 GraspNet。增加接触感知停止、路径避碰、Flip 实际姿态判定。未达到原语 Gate 前不训练高层策略。

**阶段 B — 小样本交互结果数据**：每个场景随机产生不同几何/可见性/摩擦条件，执行合法参数化候选动作，记录前后观测、真实物体变化、后续有效抓取数量/质量与最终成功。Oracle rollout 可以离线用于诊断/给候选标注真实后果，但学生策略严格只看可观测量。优先训练小型 action-conditioned outcome/value predictor，而非从零训练视觉 backbone 和六维抓取网络。训练目标包括 action success/failure、after-action grasp feasibility、物体姿态变化、代价及扰动。预测器输入同等用于所有动作类型。

**阶段 C — 统一选择的学习**：训练轻量高层决策（候选动作评分 / actor-critic），基于共同的目标取物成功信号与动作代价；可用保守 model-based action selection 或在线RL细调，均须与同计算预算的 rule-based、forward greedy/MPC、GOMP-like、GAPG-like、Uni-PNP-like、SPIN-like（按任务适配性划分）等强方法比较。不能通过强制各分支回报、人工选中唯一正确技能或在每种情况固定标准答案来制造“学会组合”。只有当弱/强基线均可重复测试后才讨论原创贡献。

稀疏主奖励为完整取出成功，失败/超预算/危险碰撞为惩罚；每次执行及观察有真实时间/动作成本；鼓励保持无关物体稳定。可以使用可抓性/可执行性变化做辅助学习信号，但必须做 reward ablation，避免仅凭显式抓取分数拟合最新已有工作 GOMP。对于 View，不把所有相机信息增益等同于任务收益，需看是否改变后续取物决策。

在单3090及Isaac GUI/渲染开销下，应先测每秒真实模拟步和每条 rollout wall-time，禁止立即设置数十万条在线渲染轨迹；GUI 用于关键案例，训练可在 Headless 多场景可行时批量运行。数据/缓存/权重仅存项目目录。

## 5. 严格三次前期实验（研发 Gate，不是正式论文评测）

E1 **物理操作必要性/可执行性**：在 C/F/V/Direct 小规模固定真实场景中，以同一 SR5、同一传感器比较 Direct Grasp、几何 Push+Grasp、Flip+Grasp、View+Grasp 的操作后成功率和实际物理结果；每类覆盖多物体/多随机种子，保留全部失败。若 Flip 无稳定可执行物体/接触例子，停止训练，不伪造姿态变化。

E2 **学习是否真正需要**：以相同候选动作/可观测信息/预算，对比明确的手工规则、等信息 greedy MPC、简单动作结果预测和小型学习评分器；Direct 控制场景不应因为引入四技能退化。若简单规则或 MPC 已经同等成功，优先缩小科学问题，不扩大网络。

E3 **完整策略与未见条件**：仅在 E1/E2 产生可信证据后，做少量 Mix / 未见 YCB 物体 / 摩擦与初态变化的配对固定种子对比。包括消融 w/o View, w/o Push, w/o Flip, w/o learned-selection, oracle-vs-RGBD，同时对接最接近的已公开强基线。报告目标完整取出成功率、动作数、wall-time、非目标扰动、真实接触、失败类型和置信区间。只有存在超越强基线的可重复现象才继续大规模训练。

**不要把 E1/E2/E3 扩展成无穷多单独实验；每 Gate 固定配置、样本预算和冻结代码/随机种子。** 具体阈值在 E1 开始前由 pilot/基线量级预先登记，不因结果好坏临时修改。

## 6. 已发表竞争工作的关键提醒

- GOMP (ECCV 2026, arXiv:2606.30474)：已使用 **graspability field + RL**，让推动/滑动/重定向进入可抓取状态并自动触发抓取。因此“改善抓取可行性奖励”和“翻转后再抓”不是原创。
- Uni-PNP (arXiv:2610.21735，2026-10-15)：接触几何预训练 + 两阶段RL，已经统一非抓取与抓取，包括 tip-assisted grasp。要查清它对主动观察、目标取出与复杂障碍条件的覆盖范围，不能只称它不支持多技能。
- MS-MEM (arXiv:2609.02493)：已经联合 active viewpoint + push + grasp，但主要以建图和扰动控制为目标。不能只说“我们加入主动感知”。
- SPIN (CoRL 2025)：技能规划蒸馏含抓取与非抓取长序列；需审查是否有近似任务。
- GAPG (ICRA 2026)：几何感知目标导向推抓；需要比简单 push+grasp 更强的对比。
- PreAfford (IROS 2024)：预抓取中的 affordance 预调整。
- Flip Anything (2026-11 arXiv)：翻转、推动、顶倒策略并非新技能；其主要任务/本体不同。

所谓 T-RO 研究价值必须是观察到强基线在明确物理现象上的可重复缺陷，而非四模块拼接的表现提升。进一步读全文、检查可用代码，确认创新缺口后再命名新算法。

## 7. 下一条 Codex 任务 M1（仅工程原语与场景，无训练）

1. 保留现有 M0、SR5、GraspNet 证据和版本，不重装环境。
2. 在已有 SR5 引擎上生成 Direct、C、F、V 和 Mix 场景 **schema** 与固定 seed、物体清单。Mix 只做场景生成和检查，不能提前训练。
3. 验证 80mm 夹爪可行宽度、SR5 IK/轨迹与碰撞、可见目标身份/标注、真实接触与稳定支撑；对于不可取物体标记 UNSUITABLE 并保留原因。
4. 实现统一 `observe()->{rgbd,mask,proprio,grasp_candidates,history}` 和 `step(ActionType,parameters)->{observation,terminal,cost,diagnostics}` 接口；区分 ORACLE_DIAGNOSTIC 和 RGBD_POLICY。
5. 加入 View、Push、Flip、Grasp 的调用协议/参数与物理结果检查，不写固定场景分支、没有新网络训练。输出 GUI + Headless 视频，随机种子与失败归档。
6. 编写 E1 protocol 与样本列表，冻结 E1 后再运行；不能预先写 PASS。将关键代码、配置、报告、小图上传 GitHub；大型视频、资产、日志只保存在项目目录。
