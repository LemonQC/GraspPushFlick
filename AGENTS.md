# GraspPushFlick / TRO-APFG — project instructions

## Scope
Research target: IEEE T-RO, active perception, pushing, physical flipping/reorientation, and 6-DoF grasping for retrieval of a designated object in clutter. Flip means a physical change in the object's 3D orientation/support state, not reverse planning. No object rearrangement objective, VLA, cross-embodiment learning, or online LLM API. Reverse grasp-conditioned planning is a separate RA-L project. No novelty or formal performance claims until evidence is available.

## M0: environment and assets
- Use the current project directory as PROJECT_ROOT. Prefer Isaac Sim 5.1.0 + Isaac Lab 2.3.1, Python 3.11 and PhysX on RTX 4090; verify the official compatibility matrix, driver, GLIBC and available disk before installing. Do not upgrade system drivers or use sudo.
- Install Conda by absolute prefix inside .conda/isaac-apfg. Keep package caches, temporary files, Kit portable-root, runtime HOME, shader caches, assets, and outputs inside PROJECT_ROOT. Do not change Codex's own HOME or user shell configuration. Audit actual writes, not just environment variables. Never delete unrelated data. Check free space before downloads.
- Prefer local reusable assets, otherwise use official downloads with bounded retries, resumption and integrity checks. Obtain version-compatible Franka Panda USD plus full dependencies, fixed RGB-D and wrist RGB-D cameras, and a table. Do not download the full Isaac asset library unless separately approved.
- Prepare YCB first (at least 12 verified objects, target about 30); GraspNet object meshes next, not full RGB-D/grasp annotations. Audit DexGraspNet 2.0 and GraspFactory; only small authorized samples if feasible. Preserve original scale and mesh, source/license, collision geometry, mass, inertia, center of mass, and friction provenance; mark estimated parameters.
- Headless smoke: actual falling-body physics; Franka joint control and gripper opening/closing; both cameras producing RGB and depth; wrist motion changes camera extrinsics; at least 12 real geometric assets load and settle; 5–8 object clutter scene. Verify local USD references and offline asset readiness. No policy training in M0.

## Headless execution and evidence
- No GUI, desktop session, X11 forwarding, or DISPLAY dependency. Use Isaac Lab AppLauncher with headless mode and enabled cameras (normally --headless --enable_cameras; verify pinned API). Headless does not mean disabling rendering. Fail explicitly if offscreen rendering cannot initialize.
- Write MP4 from real rendered RGB frames, using a project-local encoder/dependencies. Record a fixed third-person view and wrist RGB view; keep RGB-D images, camera calibration, scene seed, object IDs, control commands, joint/EE and object poses, contact records, timing and success/failure. For M0, record the robot/camera and falling/clutter physics smokes; for future rollouts record both success and failure, not only selected successes.
- Default video 640x480 or higher, 24 or 30 fps; record timestamps and actual capture frequency. Check frame count, duration and decodability. Save the original videos under outputs/<run_id>/videos/ or outputs/environment_check/ for M0. Use unique run IDs; do not overwrite results. Keep lightweight representative PNG/JPG contact sheets for remote review.
- Report PASS / FAILED / BLOCKED / NOT_RUN separately. Do not substitute synthetic frames or teleport objects to fabricate physical evidence. Ground-truth state is for diagnostic ORACLE mode or evaluation, not silently supplied to RGBD mode.

## Subsequent stages
M1 unified controller and scene generation; M2 Active; M3 Push; M4 Flip (toppling/rolling, not merely yaw); M5 Grasp and complete extraction; M6 cooperative decision; M7 published baselines and scientific contribution assessment. Physical actions must use actual joint/gripper control and physics stepping; no state resets during rollout or artificial grasp constraints. First validate primitives separately. Do not start later stages before M0 validation is complete.

This file records the agreed research and engineering requirements, not an implemented simulator or completed experiment. M0 status at repository initialization: NOT_RUN.
